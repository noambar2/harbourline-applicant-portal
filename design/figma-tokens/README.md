# Figma variables - Harbourline University Applicant Portal

The files here are generated from the values in code (`src/app/themes.ts`,
`src/styles/themes.css`, `src/app/components/primitives.tsx`) and are meant
to be imported into Figma with a plugin that supports W3C Design Tokens
(Variables Import / Tokens Studio).

## Collection structure

**Folder name = Figma collection name, file name = mode name.** This is the
structure a Figma export produces, so it is also the structure to import back:

```
figma-tokens/
├── Value.tokens.json      ← the fixed-values collection (single mode)
└── Theme/                 ← the themes collection
    ├── Light.tokens.json
    ├── Dark.tokens.json
    ├── Purple.tokens.json
    ├── Teal.tokens.json
    ├── Sunset.tokens.json
    ├── Pink.tokens.json
    └── Colourful.tokens.json
```

All seven theme files contain **exactly the same variable names** (101 per
file) - that is required for them to load as modes of the same collection.
Don't mix `Value.tokens.json` into `Theme/`: its set of variables is
different, and that breaks the import.

## What's in Primitives

- `radius` - 8 / 10 / 16 / pill, plus the Colourful theme radii (14 / 20).
- `type` - the **desktop** type scale (10→52).
- `type-mobile` - the same scale after the automatic step-down below 768px.
- `line-height`, `font-weight`.
- `space` - a 4-40 scale + card padding and page padding per breakpoint.
- `size` - icons, icon circles, button/chip/input heights, dots.
- `layout` - content width, breakpoints, dialog widths, list heights,
  carousel dimensions, ad banner height.
- `elevation` / `opacity` / `duration` / `z-index`.

## What's in each Theme

- `brand` - the colour and its transparency tints (6% / 8% / 10% / 12% / 18%).
- `accent-2` - the secondary colour (the dot at the end of a heading).
- `background` - page background and the two blob colours.
- `nav-gradient/stop-1..4` - the four stops of the nav bar.
- `surface` - card, secondary surface, glass, chip, dialog scrim.
- `ink` - primary/secondary/faint text and dividers.
- `semantic` - success / warning / error / favourite + their backgrounds.
- `elevation` - shadow colours.
- `header/bar` - navy `#122736`, the same in every theme.
- `accent/<page>` - each page's hue: `default`, `hover`, `accent-2`,
  `page-bg`, `surface` and its own nav gradient.

> In the **Colourful** theme each page has a different hue (profile purple,
> bookings orange, tasks teal, modules green, enquiries pink, messages blue,
> settings purple). In every other theme `accent/<page>` equals the theme
> colours - exactly like `accentFor()` in code. So you can design one screen
> and switch both theme and page.

## Updating

The files are generated by `generate.py`, which writes next to itself
(`Value.tokens.json` and `Theme/*.tokens.json`). When you change a colour or
token in code, regenerate them (`python3 design/figma-tokens/generate.py`)
and re-import into Figma, so the two sides don't drift apart.

## Not here yet

- **Shadows as a single object** - Figma doesn't support a shadow variable;
  the shadow colour and numbers (`elevation`) are here, and the composition
  is done in an effect style.
- **Gradients** - stored as four colour stops, not as a gradient variable.
- **The "App" theme** (navy cards on a light page) is currently disabled in
  code and so wasn't exported. If it comes back, its `surface/card` is
  `#122736` and `surface/muted` is `#1C3346`.
